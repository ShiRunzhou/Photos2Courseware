# 阶段四：讲义生成

## 任务目标

基于阶段二的聚类内容和阶段三的缺口分析，逐模块生成结构化的 Markdown 讲义。

## 输入文件

- `.workbuddy/cluster_result.json`
- `.workbuddy/gap_analysis.md`（阶段三产出）
- `.workbuddy/extracted/IMG_*.json`（按需查阅提取原文）

## 输出文件

逐个模块保存到 `.workbuddy/lecture_notes/{模块id}_{标签}.md`

## 讲义格式规范

### 文件头

```markdown
# 模块{id}：{标签}

> 生成说明 | 共 {n} 张照片提取 + 框架补全 | 日期
```

### 内容结构

每个知识点用 `## 序号. 标题` 组织，包含：
- 核心概念定义
- 关键数据用**表格**呈现（而不是大段文字）
- 对比关系用表格（并排比较）
- 流程步骤用有序列表或代码块流程图
- 专业术语标注中英文
- 保留照片中提取的原文信息，不篡改

### 框架补全内容

阶段三识别的补充内容用 `🆕 补充` 前缀的章节标题：

```markdown
## 3.4 🆕 补充：生豆物理分级全维度
```

确保：
- 补全内容与已有内容逻辑衔接
- 深入程度与已有内容匹配（不浅尝辄止也不过度深入）
- 每个补充章节独立、完整

### 视觉辅助标记

在适合配图的位置添加：

```markdown
[配图建议：SCA 杯测评分表示例]
```

不需额外操作——这是供后续人工配图时参考的标记。

### 模块小结

每个模块末尾添加总结表格：

```markdown
> **本模块总结**：一句话概括 + 核心知识点表格
```

## 质量检查

- [ ] 每个照片中的知识点都被覆盖
- [ ] 每个阶段三的补全建议都已落实
- [ ] 表格和列表优先于大段叙述文字
- [ ] 术语有中英文对照
- [ ] 章节逻辑从基础到深入、从理论到实操

## 执行示例

对每个模块，在对话中：
1. 读取该模块的聚类内容和 gap_analysis
2. 生成完整讲义 Markdown
3. 保存到指定路径
4. 用户确认后继续下一个模块
